# 什么时候放图，图边上写什么

图不是装饰。每张图都要替正文完成一件文字做不好的事：让读者**看见**形状、差距或转折。下面是放图的时机和配套文字的写法。

## 一、什么时候该放图

出现下面任一情况，就该画图：

1. **一句话里出现三个以上需要比较的数字**。读者记不住，画出来。
2. **结论依赖「形状」**：加速、见顶、交叉、背离、换代。形状用文字说不清。
3. **你要读者相信一个因果**：某件事之后数据变了。把事件画成竖线（`trend_events`）。
4. **你给出了预测或目标**。区间和假设必须摆出来（`scenario_fan`）。
5. **一个论点需要几个口径互相印证**。放一组小图（`panel_grid`）。
6. **你在讲一个分阶段的演进故事**。给读者一张路线图（`capability_ladder`）；如果阶段是用一条长期数据切出来的，用 `phase_trend`。
7. **你要说清楚钱漏在哪一步**。从一个总数拆到另一个总数（`waterfall`），或者把流程和每个环节的成本对齐（`process_cost`）。
8. **你拿一家公司和另一家「当年的它」比**。先把两段历史对齐到同一发展年份（`aligned_compare`），再谈差距。
9. **你要比较两个主体的结构，并给出三四条结论**。结构图加编号旁注（`share_compare`），结论和图在同一屏。
10. **你在讲一个没有数据、只有关系的观点**。正反馈用飞轮图（`flywheel`），高低分层用分层图（`tiers`）。

下面的情况不要放图：

- 只有一两个数字。写进句子里，加粗即可。
- 需要读者查具体数值。用表格。
- 图只是把上一张换个切法，结论相同。留更清楚的那张。
- 你自己说不出这张图的结论。

密度参考：论证型长文大约每 300 到 500 字一张图；一个小节一个论点，配一到两张图；不要连续放三张图而中间没有文字。

## 二、两种节奏

### 论证型（配 mono 主题）

用于研报正文、投资备忘、分析文章。顺序固定：

```
加粗的论点句。 论据展开两到四句，给出关键数字。
[图 N：把论点再说一遍的标题]
资料来源：…
下一段从这张图引出的推论或风险写起。
```

要点：
- **论点先于图**。读者先知道该看什么，再去看图。
- **图标题复述论点**，但更具体，带上数字或时间。正文说「本地化部署仍是收入基本盘」，图标题写「图 13：预计 2025-27 年本地化部署收入复合增速 81%」。
- 两张强相关的图**并排**放，标题各写各的结论。
- 图后的第一句话不要重复图里已经看得到的内容，直接往下推。

### 数据展示型（配 teal 主题）

用于数据简报、行业观察、给管理层看的材料。顺序：

```
小标题（名词短语，说明这一节看什么）
一到两句话的发现，把最重要的那个数字说出来。
接下来值得追问的问题（可选，一到两条）。
[图：名词标题，与小标题呼应]
```

要点：
- **发现先于图**，而且只说一个。一节一个发现。
- **追问的问题**是这种写法的特色：数据说明了「是什么」，问题指向「为什么」和「接下来怎样」。没有好问题就不写。
- 图标题可以是名词（「各行业采用率」），因为结论已经在图的正上方。

## 三、标题怎么写

| 不要这样 | 改成这样 | 原因 |
|---|---|---|
| 收入走势 | 收入三年增长 9.7 倍 | 给出读者该记住的数字 |
| 毛利率对比图 | 本地化部署业务毛利率维持在 50% 以上 | 说出方向和水平 |
| 模型价格 | 新版本每次升级提价约 20% | 说出规律 |
| 公司 A 与公司 B 的成本结构 | 公司 A 的人力成本占比远高于公司 B | 说出差异在哪 |

规则：
- 一句话，不超过两行。
- 用陈述句，有主语有谓语。
- 带数字时只带一个最关键的。
- 预测性质的结论用「预计」「我们测算」开头，和事实区分开。
- 不用「显著」「大幅」「明显」代替数字。

## 四、图内文字

图里的字越少越好，但有四类字值得写：

1. **事件名**（`events`）：名词，三个词以内。
2. **关键数值**（数据标签）：mono 柱图全标；teal 线图一般不标，要标只标终点。
3. **一句批注**（`annotation`、`note`）：读者光看形状想不到的信息，比如「宣布提价 30%」或两段复合增速。用警示红，一张图最多一处。
4. **单位**：优先用 `unit` 写在左上角。teal 主题的纵轴标题（`ylabel`）用来说明「这根轴量的是什么」，单位可以跟在后面的括号里，两种写法选一种，不要重复。

## 五、来源行

- 格式：`资料来源：数据方，整理方` 或 `Source: …`。
- 自己加工过的写「作者测算」「作者整理」。
- 数据截止日期、口径差异、样本说明，以「注：」接在来源后面。
- 示意数据必须注明「示意数据」。

## 六、一页一个论点：图、文、表同屏

一份深度报告里最好读的页面，都是「一页只证明一件事」：标题就是结论，下面的图、文字、表格都在为这一句服务。

- **标题即结论**。页标题和图标题都写判断句，带上最关键的那个数字。读者只翻标题就能读完整份报告。
- **图文表同屏**。论点需要假设和数字支撑时，把三样东西放在同一页：左边的表列假设，中间的图画结果，右边的文字写依据。`scenario_fan` 的图加驱动因素表、mono 单图的 `notes` 旁注栏都是这个用法。
- **编号联动**。图上有几处要讲，就在图上放编号圆点（`marks` 的 `num`，或 `share_compare` 的 `numbers`），旁注按同样的编号逐条写。读者看到 ③ 就知道该看图的哪里。
- **一页最多两张主图**。第三张图往往是在重复前两张的结论，挪到附录。

## 七、强调只用三种记号

强调用多了就等于没有强调。全篇只用这三种，而且每种的含义固定：

| 记号 | 含义 | 本技能里的写法 |
|---|---|---|
| 虚线框 | 「看这一段」：一个阶段、一段异常、一个时间窗口 | `phase_trend` 的阶段框，`marks` 的 `box` |
| 短红字 | 「这一段意味着什么」：一句定性，十个字以内 | 阶段的 `verdict`，`note`，`box` 的 `text` |
| 高亮色 | 「主角是谁」：主角公司、主角业务 | `highlight`，藏青主线 |

- 一张图里最多用两种。
- 红叉（`cross`）是第四种，只用来否定一种外推或误解，全篇一两次就够。
- 不要用加粗、下划线、大号字、彩色底纹去叠加强调。

## 八、先把口径做可比

比较之前先问：这两组数字放在一起，比的是同一件事吗？

- **不同年代的公司按发展年份对齐**，不按日历年（`aligned_compare`）。图例里保留真实年份，来源行写明起点怎么选。
- **披露口径不同的先换算**。一家按毛额、一家按净额确认收入，先统一，再画图；统一不了就在「注：」里写明差异。
- **拆分时先确认加总能闭合**。瀑布图的小计由函数自动算，各部分加起来对不上总数，说明口径有问题，先回去查数据。

## 九、首尾呼应

开篇提出问题，结尾用同一张图回答。

- 开头放一张「时代条最后一段带问号」的图（`eras` 的最后一项写「广告期？」并设 `open`），读者带着问题读下去。
- 结论部分再放同一张图，去掉问号，或把当时的预测区间补上，回答开头的问题。
- 两张图的配色、坐标轴、时间范围完全一致，读者才能一眼看出「变了什么」。

## 十、观点图与概念图

有些论点没有数据，只有关系：业务分层、增长飞轮、竞争格局。这时画概念图，不要硬凑数据图。

- 形状少、字少：一张概念图不超过七个框，每个框不超过六个字。
- 箭头上写动词（「带来流量」「降低成本」），框里写名词。
- 否定一种常见看法时，可以在那条外推线或那组柱子上打红叉（`cross`），旁边一句话说明为什么不成立。
- 概念图用一种颜色加灰色。正反馈画成飞轮（`flywheel`），分层画成分层图（`tiers`）；其他形状可以用 PPT 或绘图工具画，配色和字体照 `style-tokens.md`。

## 十一、哪些做法别学

参考深度报告时，下面三种做法常见，但不要照搬：

1. **信息过密**。一页放三四张图再加大段文字，读者不知道先看哪里。一页一个论点，放不下就拆页。
2. **数据标签挤成一片**。每个点都标数，数字互相压住。只标关键点：阶段端点、首尾、主角，其余让读者看形状。
3. **截图拼接**。把行情软件、别家报告的截图直接贴进来，字体、颜色、清晰度都和全篇不一致。重画一遍，数据来源写在来源行。

## 十二、跨图一致

- 同一个实体，全篇同一个颜色。主角公司始终是藏青或深青，对照方始终是橙。
- 同一类时间轴，标签格式一致（都用 `Jan-25` 或都用 `2025-01`）。
- 图号连续，正文引用图号。
- 一份文档只用一个主题。确实需要混用时，正文用 mono，附录或数据专页用 teal。
